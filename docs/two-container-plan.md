# 历史方案：双容器部署

> 双容器候选方案已由 boxlist 原生单容器方案取代，不是当前部署承诺。安装见 [快速开始](quickstart.md)，后端接入、上游基线与许可证见 [后端变更](backend-changes.md)。

早期设计将 OpenList 与图标 sidecar 分成两个服务。当前图标功能直接接入 Go 后端，在一个容器内由一个原生进程提供完整前端与同源 `/icon/`，无需额外图标容器或网关进程。

通用技术边界仍适用：仅处于同一 Docker 网络不会自动形成浏览器同源入口；HTTPS、域名和证书由部署者配置；镜像归档不包含数据卷；已有实例迁移必须先备份并验证回滚。容器数量不能代替真实运行、权限与持久化验收。
