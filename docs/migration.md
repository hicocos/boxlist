# 数据迁移、备份与恢复

当前部署见 [快速开始](quickstart.md)。后端基线、素材格式和兼容边界见 [后端变更](backend-changes.md)。迁移必须先在隔离副本验证，不能用新安装覆盖已有数据。

## 备份范围

- 保存固定镜像版本，以及经过保密检查的部署配置、环境变量和挂载信息。
- 完整备份专属 Docker 命名卷中的 OpenList 配置、数据库及私有 `icon/` 素材数据。命名卷由 Docker 管理，新安装不需要手工创建或修改宿主机目录权限。
- 先停止目标实例的写入再做完整一致性备份；外部数据库按对应数据库的备份方式处理。运行中的 SQLite 不能只复制主数据库文件而忽略 WAL。
- 若使用外部静态前端覆盖，还需保留对应完整构建产物；反向代理与 TLS 配置另行备份。

`docker save` 只保存镜像，不包含命名卷或绑定挂载中的数据。离线恢复需要同时保留镜像或可重建源码、配置和完整数据备份。不要把数据库、原图、回收数据或含凭据的备份暴露到静态站点。

## 界面配置与浏览器偏好

相同前端不等于相同显示效果。目标实例应通过合法管理员登录逐项迁移：

- `customize_head` 中的毛玻璃与图标托管配置；优先使用各自管理入口保存。
- `customize_body` 中的自定义内容；导出前检查脚本、外部地址与访问密钥。
- 分页、预览等显示设置；不要为同步界面而整体覆盖业务配置。

不要复制另一实例的账号、权限、JWT、存储凭据或整份测试数据库。浏览器布局、排序、播放偏好与阅读进度按站点来源保存；不要整体导出并导入浏览器存储，其中可能包含登录信息。

## 旧图标服务迁移

旧独立服务属于历史方案，见 [历史说明](icon-service.md)。旧 schema 的兼容读取不等于迁移已完成，旧 `/icon-library/` URL 与当前 `/icon/` 路由也不能直接视为等价。

- 停止旧写入方后，备份完整 catalog、原图、预览、隐藏记录、tombstone 和 trash；不要只复制可见 WebP。
- 保持素材 ID 不变，并单独核对已保存图标选择和预览引用。
- 在隔离数据副本中验证目录、真实管理员操作、引用删除保护与重启持久化，再切换目标实例。
- 不允许两个进程同时写同一份素材数据。失败时先停止新写入方，再恢复旧版本与对应数据。

## 更新与回滚边界

升级前保留旧固定镜像和完整对应数据备份。若新版本改变数据库格式，回滚不能只换旧镜像；应确认目标已停止，再恢复经过验证的数据副本。首次安装工具不是已有实例的自动迁移工具。

删除素材保留的回收数据仍计入配额，不自动释放容量。不可直接删除数据库记录或 tombstone 绕过限制。预览为 immutable 缓存，删除无法撤回已经下载的字节；验收源端状态时需绕过缓存。图标删除检查与其它设置 API 不是跨请求原子事务，不能宣称完全消除竞争窗口。
