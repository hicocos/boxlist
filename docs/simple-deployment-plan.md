# 简化部署方案（待实现，不是当前版本安装说明）

本文件记录确认的命名和安装体验；不表示当前版本已具备独立域名连接功能，不自动部署或修改正在运行的实例。

## 前端：下载 Releases，不要求编译

- Releases 发布完整已编译前端压缩包及 SHA256SUMS。
- 压缩包根目录直接包含 index.html、assets/、static/，避免 dist/dist 双层。
- 用户将文件解压到现有 OpenList 宿主机数据目录下的 dist/。
- 如果宿主机数据目录挂载到容器 /opt/openlist/data，则 dist_dir 设置为 /opt/openlist/data/dist。
- 保留其它配置、数据库、账号和存储，重启目标 OpenList 容器使 HTML 模板生效。
- dist/ 是明确约定，不是 OpenList 固定限制。路径必须以已有挂载为准。

## 图标服务：独立 Docker，不修改官方后端

- 提供已构建镜像及一条 Docker 启动命令。命令只要求用户替换数据目录、实际 OpenList 后端地址和网站 Origin；可配置监听端口避免现有实例冲突。
- 用户为图标服务准备自己的域名，解析到服务器，用反向代理转到服务的本地端口，申请并启用 HTTPS 证书。
- 图标 API 与预览统一迁移到 /icon/ 命名空间；不能只改文档，必须同时更新前端请求、预览 URL、服务路由、代理样例和测试。
- 示例公开服务地址为 https://icons.example/icon，图标管理页增加服务连接设置、测试连接与明确错误。默认只接受同源路径或明确授权的 HTTPS 服务，不把浏览器的 loopback 当服务器本机。
- 连接地址需随实例保存，使普通访客也能加载该服务的图标预览；保存到 customize_head 的独立非执行托管块，不保存管理员 token。
- 独立域名模式要求精确网站 Origin 的 CORS/preflight，不允许通配符放行认证请求；前端发送登录凭据前必须明确提示服务地址与风险并获得管理员确认。连接测试不得先静默发送凭据。
- HTTPS、浏览器安全上下文和真实 OpenList 管理员鉴权保持，不能为简化步骤加入鉴权绕过。

## README：首页只保留按顺序操作

1. 下载 Releases 前端包。
2. 解压到现有数据目录 dist/。
3. 修改 dist_dir，重启目标容器。
4. 一条命令启动独立图标容器。
5. 配图标域名 DNS、反向代理、SSL（明确写成必做步骤，不隐藏在高级说明）。
6. 在 OpenList 图标管理页输入 HTTPS 接口地址，测试连接并保存。

展示一个清晰宿主机/容器路径例子，补充宝塔反代步骤与粘贴位置。高级技术、备份回滚、详细 API 契约另放 docs/。
